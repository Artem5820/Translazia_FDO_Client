# Структурированный промпт V1

## Назначение промпта

Первая версия промпта использовалась для начальной доработки модуля. Основная цель состояла в том, чтобы сократить итоговый JSON, сделать пользовательский вывод русскоязычным и добавить отдельный режим для компактного представления проблем.

## REASONS Canvas

### Requirements

- уменьшить размер итогового JSON;
- оставить в компактном режиме только значимые поля;
- перевести пользовательские поля и описания на русский язык;
- добавить отдельный режим вывода только с проблемами;
- сохранить полный режим анализа для отладки;
- не нарушить работу существующего CLI.

### Entities

- `VideoAnalyzer`
- `FrameObservation`
- `SegmentRecord`
- `AnalysisResult`
- `summary`
- `issue_segments`
- `alerts`
- `events`

### Approach

- не переписывать архитектуру анализатора полностью;
- вынести сериализацию результата в отдельный слой;
- добавить переключение формата вывода через CLI;
- сохранить действующую логику анализа кадров и сегментов.

### Structure

- основная логика анализа сохраняется в `analyzer.py`;
- схемы вывода размещаются в `schemas.py`;
- переключение форматов вывода реализуется в `cli.py`.

### Operations

- добавить режим `alerts` как компактный JSON;
- локализовать пользовательские поля итогового вывода;
- добавить режим `events`;
- добавить параметр `--only-on-problem`.

### Norms

- не дублировать избыточные данные;
- использовать понятные наименования полей;
- сохранять обратную совместимость CLI;
- избегать лишних изменений в уже работающих частях проекта.

### Safeguards

- не включать в компактный JSON полный массив наблюдений;
- сохранить полный режим анализа;
- не изменять внутренние сущности без необходимости;
- не нарушать существующие сценарии интеграции.

## Текст промпта

Необходимо доработать существующий Python-модуль анализа учебных видеотрансляций. В проекте уже реализованы анализатор, сегментация и итоговая сводка. Требуется:

1. реализовать компактный JSON-режим только с проблемами;
2. перевести пользовательские поля и описания на русский язык;
3. добавить режим `events`, в котором по сегментам формируются события проблем и событие завершения трансляции;
4. сохранить существующий CLI и расширить его параметром `--format`;
5. не ломать полный режим, а вынести сериализацию в отдельный слой;
6. при необходимости добавить тесты на новые форматы вывода.

Перед внесением изменений необходимо изучить текущие сущности, структуру результатов и логику анализа, после чего реализовать минимально инвазивные изменения, пригодные для дальнейшей интеграции в другой проект.
