# REASONS Canvas

## R - Requirements

Создать и доработать desktop-клиент Translazia FDO для оператора онлайн-трансляций. Клиент должен получать расписание из VK-бота или локального файла, давать ручной выбор аудиторий, запускать несколько VK Call окон, показывать отдельное окно уведомлений, поддерживать нейросетевые проверки и полуавтоматически ставить запись звонка.

Ключевые требования:

- не допускать массовых повторов запроса расписания;
- считать ответ `Онлайн занятий в выбранном периоде нет.` финальным результатом;
- дать ручной режим выбора аудиторий, времени и описания;
- сделать удобные элементы управления автозаписью;
- использовать полуавтомат записи вместо ненадежных автокликов по координатам;
- собрать приложение в EXE;
- подтвердить результат тестами и функциональной проверкой.

## E - Entities

- `StreamEntry` - аудитория и ссылка трансляции.
- `ScheduleRequest` - запрос расписания через VK-бота.
- `ManualClassSelection` - выбранные вручную аудитории, время и описание.
- `StreamWindow` - окно VK Call на QWebEngineView.
- `NotificationWindow` - окно уведомлений, ошибок и служебных команд.
- `RecordingRequest` - команда постановки записи для одной или нескольких аудиторий.
- `RecordingAssistant` - полуавтоматический помощник заполнения диалога записи.
- `AnalysisResult` - результат нейросетевой проверки.
- `BuildArtifact` - собранный EXE-пакет.

## A - Approach

1. Сохранить текущую MVC-структуру проекта.
2. Обновить требования и промпты до актуальной версии.
3. В VK-расписании ограничить повторные отправки и добавить ранний выход при сообщении об отсутствии занятий.
4. Реализовать ручной выбор аудиторий через отдельный диалог.
5. Переработать панель записи в два ряда, чтобы кнопки и спинбоксы не пересекались.
6. Для записи звонка использовать полуавтоматический сценарий: приложение не ищет шестеренку и не кликает по координатам, а ждет готовый VK-диалог.
7. Добавить PyInstaller-спецификацию и скрипт сборки.
8. Зафиксировать тестовые сценарии, выполнить unit-тесты, compileall и smoke-test EXE.

## S - Structure

- `translazia_client/controllers/main_controller.py` - основной сценарий расписания, запуска окон и записи.
- `translazia_client/views/main_window.py` - основное окно и ручной режим.
- `translazia_client/views/manual_stream_dialog.py` - ручной выбор аудиторий.
- `translazia_client/views/notification_window.py` - панель уведомлений, счетчики, кнопки записи.
- `translazia_client/views/stream_window.py` - VK Call окно и полуавтомат заполнения записи.
- `translazia_client/views/vk_auth_window.py` - авторизация и запросы VK-боту.
- `translazia_client/config.py` - пути в исходном и frozen-режиме.
- `TranslaziaFDO.spec` и `build_exe.ps1` - сборка EXE.
- `spdd/prompts/` - отдельная папка версионируемых промптов.
- `tests/` - автоматические проверки.

## O - Operations

Основной поток:

1. Оператор запускает приложение.
2. Клиент проверяет готовность окружения.
3. Клиент запрашивает расписание у VK-бота или читает локальный seed.
4. Если занятий нет, показывает сообщение по центру окна выбора.
5. Если нужен ручной режим, оператор выбирает аудитории, время и описание.
6. Клиент открывает окна трансляций и окно уведомлений.
7. Оператор может нажать `Запись` вручную или настроить автозапись и подтвердить `OK`.
8. Для каждой аудитории клиент показывает подсказку: открыть шестеренку и пункт `Записать звонок`.
9. После появления VK-диалога клиент заполняет название и нажимает `Записать звонок`.
10. Клиент проверяет статус записи и пишет результат в уведомления.

## N - Norms

- Интерфейс должен быть практичным, без слипшихся кнопок и нечитабельных полей.
- Все даты для записи берутся от текущей даты запуска.
- Время автозаписи проверяется относительно текущего московского времени.
- Все ошибки и предупреждения видны оператору.
- Промпты и требования обновляются перед доработкой кода.
- Тесты должны проверять не только наличие файлов, но и ключевые правила SPDD.

## S - Safeguards

- Не использовать хаотичные координатные клики по VK.
- Не отправлять бесконечные запросы VK-боту.
- Не повторять запрос после ответа об отсутствии занятий.
- Не включать автозапись при каждом изменении спинбокса.
- Не скрывать поля времени при активной автоустановке.
- Не считать запись установленной без признаков успешного результата.
- Не поставлять EXE без smoke-test запуска.
