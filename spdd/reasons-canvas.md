# REASONS Canvas

## R - Requirements

Создать desktop-клиент для вечерних трансляций ФДО. Клиент читает аудитории и ссылки, дает оператору снять отмененные занятия, открывает выбранные трансляции в отдельных окнах, добавляет отдельное окно уведомлений, равномерно раскладывает окна по мониторам и показывает результаты нейросетевого анализа.

Definition of Done:

- 12 аудиторий из seed-файла распознаются корректно;
- запуск учитывает `N + 1` окно, где `+1` - уведомления;
- архитектура разделена по MVC/blueprint;
- нейросетевые ошибки и проблемы видны в UI;
- тесты проходят.

## E - Entities

- `StreamRoom` - аудитория и ссылка трансляции.
- `AppSettings` - настройки источника, запуска и анализа.
- `AnalysisSummary` - нормализованный результат видеоанализа.
- `MainWindow` - главное представление.
- `StreamWindow` - окно трансляции.
- `NotificationWindow` - окно уведомлений и ошибок.
- `MainController` - сценарии загрузки, запуска и обработки анализа.
- `ScheduleService` - загрузка списка трансляций.
- `StreamCaptureSession` - захват видеофрагмента окна.

## A - Approach

1. Разделить код по MVC.
2. Оставить `app.py` минимальным bootstrap-файлом.
3. Добавить desktop blueprint, который создает контроллер.
4. В контроллере держать сценарии, состояние открытых окон и обработку событий.
5. В представлениях оставить UI и сигналы.
6. В сервисах держать операции чтения расписания и захвата.
7. При запуске выбранных аудиторий рассчитывать раскладку для `len(selected) + 1`.
8. Любой результат анализа отправлять в основной журнал и окно уведомлений.

## O - Operations

1. Создать `controllers/bridge.py` для Qt-сигналов.
2. Создать `services/schedule_service.py`.
3. Перенести захват видео в `services/capture.py`.
4. Создать `views/main_window.py`, `views/stream_window.py`, `views/settings_dialog.py`.
5. Создать `views/notification_window.py`.
6. Создать `controllers/main_controller.py`.
7. Создать `blueprints/desktop.py`.
8. Обновить `app.py`, чтобы он регистрировал blueprint.
9. Добавить тесты на seed-файл, раскладку окон и SPDD-артефакты.

## N - Norms

- Названия классов Qt-окон заканчиваются на `Window` или `Dialog`.
- Контроллеры не строят виджеты напрямую, только управляют сценариями.
- Сервисы не зависят от главного окна.
- Русский текст UI хранится в UTF-8.
- Ошибки не скрываются: они идут в журнал и окно уведомлений.
- Тесты запускаются стандартным `unittest`.

## S - Safeguards

- Не изменять старое приложение расписания.
- Не удалять файл seed-ссылок.
- Не запускать трансляции без выбранных аудиторий.
- Не блокировать UI тяжелым анализом, использовать `ThreadPoolExecutor`.
- Не терять результаты анализа, сохранять JSON рядом с фрагментом.
- При изменении требований обновлять REASONS Canvas и prompts перед кодом.
