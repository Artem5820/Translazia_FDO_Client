# SPDD-артефакты проекта Translazia FDO

Папка фиксирует разработку desktop-клиента Translazia FDO по методологии Structured-Prompt-Driven Development (SPDD). Промпты, требования, анализ, тестовые сценарии и итоги проверки хранятся как версионируемые артефакты проекта.

Источник методологии: Martin Fowler, Thoughtworks, статья `Structured-Prompt-Driven Development (SPDD)`, 28.04.2026: https://martinfowler.com/articles/structured-prompt-driven/

## Выбранная задача

Доработка существующего клиента онлайн-трансляций ФДО в рамках курсового проекта:

- загрузка аудиторий и VK Call ссылок из локального файла;
- запрос расписания через VK-бота с корректной остановкой при ответе "Онлайн занятий в выбранном периоде нет.";
- ручной выбор аудиторий, времени и описания занятия, если расписание не получено автоматически;
- запуск выбранных трансляций в отдельных QWebEngineView-окнах;
- отдельное окно уведомлений и ошибок для оператора;
- полуавтоматическая постановка записи звонка в VK: оператор открывает диалог записи, программа заполняет название и подтверждает;
- настройка времени автозаписи с проверкой действительности интервала;
- подключение нейросетевого анализа видеофрагментов;
- сборка приложения в EXE через PyInstaller;
- сохранение архитектуры MVC/blueprint.

## Структура SPDD

- `requirements.md` - исходные и уточненные требования, Definition of Done.
- `analysis.md` - анализ контекста, доменных сущностей, бизнес-правил, рисков и решений.
- `reasons-canvas.md` - итоговый структурированный REASONS Canvas.
- `prompts/` - отдельная папка с версионируемыми промптами.
- `test-scenarios.md` - тестовые и ручные сценарии проверки.
- `verification.md` - результаты функциональной проверки и матрица соответствия.
- `conclusion.md` - вывод по лабораторной работе.

## Версии промптов

Промпты хранятся в `spdd/prompts/`:

1. `001-initial-client.md` - первичная постановка desktop-клиента.
2. `002-mvc-blueprint-notifications.md` - архитектура MVC, blueprint-слой и уведомления.
3. `003-spdd-compliance.md` - синхронизация реализации с SPDD.
4. `004-operational-hardening.md` - готовность окружения, проверки, журнал событий.
5. `005-operator-workflow-polish.md` - улучшение операторского UX.
6. `006-fdo-branding-refresh.md` - визуальное оформление под ФДО.
7. `007-vk-web-authorization.md` - авторизация и запросы расписания через VK Web.
8. `008-recording-semi-automatic-and-exe-build.md` - полуавтомат записи и EXE-сборка.
9. `009-lab8-final-report.md` - финальное оформление лабораторной работы и отчета.

## Выбранная LLM

ChatGPT / Codex.

## Правило синхронизации

При изменении требований сначала обновляется соответствующий prompt/Canvas, затем код и тесты. Если реализация расходится с намерением, сначала исправляется prompt-артефакт. Это делает промпты проверяемой частью разработки, а не одноразовыми сообщениями.
