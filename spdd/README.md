# SPDD-артефакты клиента Translazia FDO

Эта папка фиксирует разработку клиента по методологии Structured-Prompt-Driven Development.

Источник методологии: Martin Fowler, Thoughtworks, статья `Structured-Prompt-Driven Development (SPDD)`, 28.04.2026: https://martinfowler.com/articles/structured-prompt-driven/

## Выбранная задача

Доработка существующего клиента онлайн-трансляций ФДО в рамках курсового проекта:

- чтение расписания/ссылок аудиторий из локального файла или VK-бота;
- выбор аудиторий перед запуском;
- запуск от 2 до 12 трансляций и дополнительного окна уведомлений;
- равномерная раскладка окон по мониторам;
- подключение нейросетевых модулей анализа видео;
- вывод найденных проблем в клиенте;
- поддержка MVC/blueprint-архитектуры.

## Структура SPDD

- `requirements.md` - исходные требования и Definition of Done.
- `analysis.md` - анализ контекста, доменных сущностей, правил и рисков.
- `reasons-canvas.md` - структурированный промпт REASONS.
- `prompts/` - версионируемые версии промптов.
- `test-scenarios.md` - тестовые сценарии на основе требований.
- `verification.md` - функциональная проверка и матрица соответствия.
- `conclusion.md` - вывод по лабораторной работе.

## Выбранная LLM

ChatGPT / Codex.

## Правило синхронизации

При изменении требований сначала обновляется соответствующий prompt/Canvas, затем код и тесты. Это следует SPDD-правилу: если реализация расходится с намерением, сначала исправляется prompt-артефакт.
