# Исходные требования

## Цель модуля

Разработать отдельный desktop-клиент для управления вечерними онлайн-трансляциями ФДО. Клиент должен заменить ручной запуск ссылок в браузере и стать единым рабочим местом оператора трансляций.

## Функциональные требования

1. Клиент должен считывать список аудиторий и VK Call ссылок из файла `data/streams_seed.txt`.
2. Клиент должен поддерживать получение списка трансляций через VK-бота.
3. Перед запуском трансляций клиент должен показывать список аудиторий с чекбоксами.
4. По умолчанию все аудитории должны быть выбраны.
5. Оператор может снять галочку с аудитории, если занятие отменено.
6. При запуске клиент должен открыть выбранные трансляции в отдельных окнах.
7. Клиент должен всегда открывать одно дополнительное окно `Уведомления и ошибки`.
8. Окна должны равномерно занимать доступное пространство экрана.
9. При наличии двух мониторов окна должны распределяться по двум экранам.
10. Клиент должен иметь настройки интервала проверок, длительности фрагмента, FPS захвата и параметров нейросети.
11. Клиент должен захватывать видеофрагменты из окон трансляций и передавать их в модуль `vk_video_analyzer`.
12. Если нейросеть находит проблему, клиент должен показать ее в основном окне и в окне уведомлений.
13. Ошибки загрузки расписания, захвата и анализа должны попадать в окно уведомлений.
14. Клиент должен напоминать оператору перед временем запуска трансляций.
15. Перед ручным или автоматическим запуском клиент должен показать финальное окно подтверждения аудиторий.
16. Клиент должен выполнять проверку готовности окружения на старте.
17. Автозапуск должен рассчитываться по московскому времени.

## Нефункциональные требования

1. Архитектура должна соответствовать MVC: модели, представления, контроллеры и сервисы должны быть разделены.
2. В приложении должен быть blueprint-слой для регистрации desktop-модуля.
3. Код не должен концентрироваться в одном огромном файле.
4. UI должен быть современным, спокойным и практичным для ежедневной работы.
5. SPDD-промпты должны храниться как версионируемые артефакты.
6. Для ключевой логики должны быть тестовые сценарии.

## Definition of Done

- приложение запускается через `start_client.bat` или `python run_client.py`;
- файл ссылок распознается как 12 аудиторий;
- тесты проходят командой `python -m unittest discover -s tests -v`;
- структура проекта содержит `blueprints`, `controllers`, `views`, `services`, `ui`;
- при запуске выбранных трансляций учитывается дополнительное окно уведомлений;
- результаты нейросетевого анализа попадают в журнал и окно уведомлений;
- перед запуском появляется финальная проверка аудиторий;
- окно уведомлений показывает ошибки готовности окружения и находки нейросетей;
- SPDD-артефакты присутствуют в папке `spdd/`.
