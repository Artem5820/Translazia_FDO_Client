# Исходные и уточненные требования

## Цель модуля

Разработать desktop-клиент для управления вечерними онлайн-трансляциями ФДО. Клиент должен заменить ручной запуск ссылок в браузере и дать оператору единое рабочее место для выбора аудиторий, запуска трансляций, контроля ошибок, постановки записи звонков и просмотра результатов проверок.

## Функциональные требования

1. Клиент считывает список аудиторий и VK Call ссылок из `data/streams_seed.txt`.
2. Клиент умеет запрашивать расписание через VK-бота `V505_Control`.
3. Для автоматического запроса расписания должно отправляться ограниченное число сообщений, чтобы не создавать 10-15 повторов.
4. Если бот отвечает `Онлайн занятий в выбранном периоде нет.`, ожидание прекращается, повторные запросы не отправляются, в интерфейсе отображается `Занятий нет`.
5. Если расписание не получено, оператор может открыть ручной режим выбора аудиторий.
6. В ручном режиме оператор выбирает аудитории, задает время и описание занятия.
7. Окно ручного выбора должно быть достаточно широким, чтобы были видны поля времени и описания.
8. Перед запуском трансляций клиент показывает список аудиторий с чекбоксами.
9. По умолчанию все найденные аудитории выбраны.
10. Оператор может исключить отмененные аудитории.
11. Клиент открывает выбранные трансляции в отдельных QWebEngineView-окнах.
12. Клиент всегда открывает дополнительное окно `Уведомления и ошибки`.
13. Окна трансляций равномерно размещаются на доступных мониторах.
14. Переключение между многооконным и полноэкранным режимом не должно приводить к длительному подвисанию.
15. На каждом окне трансляции есть кнопка обновления вкладки.
16. Кнопка закрытия трансляций размещается в окне уведомлений, а не в основном окне.
17. Окно уведомлений показывает счетчики событий, ошибок и нейросетевых находок с понятными мелкими подписями.
18. Клиент содержит настройки интервала проверок, длительности фрагмента, FPS и параметров нейросети.
19. Клиент захватывает видеофрагменты из окон трансляций и передает их в `vendor/Module_video_analys/vk_video_analyzer`.
20. Ошибки загрузки расписания, захвата, анализа и запуска попадают в окно уведомлений.
21. Настройка автозаписи содержит кнопку ручной постановки записи, переключатель автоустановки, два спинбокса времени и кнопку `OK`.
22. Время автозаписи по умолчанию равно 17:55.
23. Спинбоксы времени должны быть достаточно широкими, редактируемыми вручную и не слипаться с кнопками.
24. Автозапись включается только после нажатия `OK`; простое изменение времени не запускает постановку записи.
25. Если указанное время уже прошло в текущей дате, клиент сообщает, что интервал недействителен.
26. Для записи звонка используется полуавтоматический сценарий: оператор вручную нажимает шестеренку VK и пункт `Записать звонок`, а программа ожидает диалог `Создать запись звонка`.
27. Когда диалог создания записи появился, программа сама заполняет название в формате `Аудитория ДД_ММ_ГГГГ`, например `В-503А 04_06_2026`, и нажимает `Записать звонок`.
28. Через контрольный интервал клиент проверяет, появилась ли запись или индикатор записи. Если запись не поставилась, оператор получает понятное предупреждение.
29. Клиент собирается в EXE-файл для запуска без ручной команды Python.

## Нефункциональные требования

1. Архитектура соответствует MVC: модели, представления, контроллеры и сервисы разделены.
2. В приложении есть blueprint-слой регистрации desktop-модуля.
3. Код не концентрируется в одном огромном файле.
4. UI должен быть практичным для ежедневной работы оператора.
5. SPDD-промпты хранятся как версионируемые артефакты в отдельной папке `spdd/prompts/`.
6. Для ключевой логики есть автоматические или ручные тестовые сценарии.
7. Сборка EXE должна включать данные, настройки и vendor-модули, необходимые для запуска.

## Definition of Done

- приложение запускается через `python run_client.py` и через собранный `dist/TranslaziaFDO/TranslaziaFDO.exe`;
- файл ссылок распознается как набор аудиторий;
- VK-бот запрашивается без массового дублирования сообщений;
- ответ `Онлайн занятий в выбранном периоде нет.` прекращает ожидание расписания;
- ручной выбор аудиторий доступен и поля ввода видны;
- полуавтоматическая запись показывает подсказку, ожидает диалог VK и заполняет название записи;
- окно уведомлений показывает ошибки, предупреждения и итоги проверок;
- команда `python -m unittest discover -s tests -v` проходит успешно;
- команда `python -m compileall translazia_client tests` проходит успешно;
- EXE собирается командой `powershell -ExecutionPolicy Bypass -File build_exe.ps1`;
- SPDD-артефакты и промпты находятся в `spdd/`.
