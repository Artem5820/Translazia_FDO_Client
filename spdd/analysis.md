# Анализ требований и контекста кодовой базы

## Контекст

Клиент создается как отдельное desktop-приложение и не должен переделывать существующее приложение расписания. Источник расписания для первой версии - файл со ссылками, далее - VK-бот. В проект уже добавлены нейросетевые модули:

- `vendor/Module_video_analys/vk_video_analyzer` - анализ видеофрагментов трансляций;
- `vendor/SoundChecker/soundchecker` - аудиоанализатор для следующего этапа.

## Доменные сущности

- Аудитория - кабинет ФДО, например `В-506`.
- Трансляция - VK Call ссылка, привязанная к аудитории.
- Сеанс запуска - набор выбранных аудиторий, которые оператор запускает одновременно.
- Окно трансляции - отдельное WebView-окно с VK Call.
- Окно уведомлений - отдельное служебное окно для ошибок и результатов нейросетей.
- Проверка - процесс захвата фрагмента и передачи его в анализатор.
- Результат анализа - статус, число проблем, JSON payload, путь к фрагменту.

## Бизнес-правила

1. Перед запуском оператор должен иметь возможность исключить отмененные аудитории.
2. По умолчанию все аудитории считаются активными.
3. Окно уведомлений открывается всегда вместе с трансляциями.
4. Нейросетевые находки должны быть видимы без поиска файлов JSON вручную.
5. Ошибки должны не теряться в консоли, а попадать в клиент.
6. Интервал и длительность проверок настраиваются в UI.

## Технические риски

- VK может требовать авторизацию в WebView.
- Захват аудио из WebView требует отдельного аудиомаршрута или `ffmpeg`.
- Нейросетевой анализ может быть тяжелым для CPU/GPU, поэтому задан лимит параллельности.
- При большом числе окон возможна высокая нагрузка на систему.
- VK API требует корректный token и peer_id, иначе загрузка через бота невозможна.

## Стратегические решения

1. Использовать PySide6 и QWebEngineView, чтобы не зависеть от Яндекс.Браузера.
2. Хранить UI в `views`, сценарии в `controllers`, внешние операции в `services`.
3. Использовать `blueprints/desktop.py` как точку регистрации desktop-модуля.
4. Сохранять исходный файл ссылок как seed-источник.
5. Захватывать видеофрагменты окон через OpenCV и передавать их в `vk_video_analyzer`.
6. Выводить проблемы в два места: основной журнал и отдельное окно уведомлений.
