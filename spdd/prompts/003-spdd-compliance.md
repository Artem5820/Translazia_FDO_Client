# Prompt v003 - Соответствие лабораторной работе SPDD

## Причина изменения

Для лабораторной работы требуется доказать применение Structured-Prompt-Driven Development: требования, анализ, REASONS Canvas, версии промптов, тестовые сценарии, проверка и вывод должны быть сохранены как артефакты проекта.

## Requirements

- Создать папку `spdd/`.
- Зафиксировать исходные требования к клиенту.
- Зафиксировать анализ контекста кодовой базы.
- Составить REASONS Canvas.
- Сохранить версии промптов.
- Создать тестовые сценарии.
- Создать матрицу проверки соответствия.
- Добавить тест, который проверяет наличие обязательных SPDD-артефактов.

## Entities

- SPDD artifact
- Prompt version
- Requirement
- Acceptance criterion
- Verification scenario
- Traceability matrix

## Approach

Документировать фактическую разработку клиента как SPDD-цикл: v001 - базовый клиент, v002 - архитектура и уведомления, v003 - SPDD-соответствие. Добавить автоматическую проверку наличия ключевых файлов и секций REASONS.

## Structure

```text
spdd/
  README.md
  requirements.md
  analysis.md
  reasons-canvas.md
  prompts/
  test-scenarios.md
  verification.md
  conclusion.md
tests/test_spdd_artifacts.py
```

## Operations

1. Создать SPDD-документы.
2. Добавить ссылки на статью Fowler и на локальные файлы проекта.
3. Описать выбранную задачу курсового проекта.
4. Описать функциональную проверку.
5. Добавить `unittest` для структуры SPDD.

## Norms

- Документы должны быть читаемыми без внешнего инструмента.
- Формат Markdown.
- Русский язык.
- Требования должны трассироваться к коду или тестам.

## Safeguards

- Не выдавать документацию за замену работающего кода.
- Не скрывать ограничения: аудиозахват требует отдельного этапа.
- Не удалять существующие тесты.
