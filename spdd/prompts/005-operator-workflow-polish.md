# Prompt v005 - Полировка операторского сценария

## Причина изменения

Клиент уже открывает трансляции и окно уведомлений, но операторский сценарий требует большей устойчивости: если оператор снял галочки и обновил расписание, выбор не должен сбрасываться. Также нужен быстрый доступ к папке результатов анализа и экспорт уведомлений для отчета.

## Requirements

- Сохранять выбранные/снятые аудитории при обновлении списка трансляций.
- Добавить кнопку открытия папки результатов анализа.
- Добавить экспорт уведомлений в текстовый файл.
- Обновить `start_client.bat`, чтобы он запускал Python из `.venv`, `venv` или системный Python.
- Добавить тесты на сохранение выбора и экспорт уведомлений.

## Entities

- stream selection key
- output folder
- notification export
- operator workflow

## Approach

Использовать устойчивый ключ аудитории `room|url`, чтобы после обновления расписания применить прежнее состояние чекбоксов. Экспорт уведомлений реализовать в окне уведомлений как UI-операцию. Открытие папки результатов оставить в контроллере, потому что это сценарий приложения.

## Structure

```text
translazia_client/views/main_window.py
translazia_client/views/notification_window.py
translazia_client/controllers/main_controller.py
tests/test_ui_behaviour.py
start_client.bat
```

## Operations

1. Добавить `selected_stream_keys`.
2. Обновить `set_streams`, чтобы принимать выбранные ключи.
3. При обновлении расписания передавать прежний выбор из контроллера.
4. Добавить кнопку `Результаты`.
5. Добавить кнопку `Экспорт` в окно уведомлений.
6. Добавить UI-тесты.

## Norms

- Состояние оператора не должно теряться при refresh.
- Доступ к результатам должен быть очевиден из главного окна.
- Экспорт не должен требовать ручного поиска логов.

## Safeguards

- Если расписание загрузилось впервые, все аудитории остаются выбранными.
- Если оператор снял все галочки, refresh не должен выбрать их обратно.
- Тесты не должны зависеть от реальных VK-ссылок.
